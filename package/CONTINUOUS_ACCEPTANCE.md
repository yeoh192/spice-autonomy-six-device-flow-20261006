# 持续验收主调度器

通过任务policy.continuous_until_acceptance=true，或统一run/preflight命令的--continuous启用。旧批次默认有界行为保持兼容；UC2845新启动器默认启用持续验收。

主调度器掌握结束权。局部defer、审查拒绝、回退、分析次数及试验次数耗尽只结束一批调度，自动进入下一批；每批保留历史、累积物理调用量和故障证据。计数和总时间不再作为持续模式的停止条件，但HTTP超时、单项仿真超时及有限局部尝试仍保留，防止一个子步骤占住流程。

成功交付要求所有活动测试完成且pass、已声明清单完成审阅与绑定验证、来源策略满足。资料缺失（缺机读条件、参考曲线或判定依据）保存为paused_missing_information；Ctrl+C保存为interrupted。两者都不表示成功。不能保证模型一定收敛。

一项执行/偏置检查失败不阻塞其他已完成测量的优化。受限模型修改经提案审查、全部活动测试尝试和结果审查后，允许保留局部改善的工程候选；已有失败项仍为not_evaluated。新增执行失败、已通过指标退化或完整回归缺项禁止保留。不得修改冻结的参考值、手册条件、端口或验收阈值来换取通过。现有夹具修复入口仍受合同约束；主流程将冻结夹具故障及真实电路证据交给模型/故障诊断，未声称能修复任意执行器代码。

API传输、认证、配置错误采用最长30秒退避后继续重试；实际长期认证错误需要平台/凭据恢复，程序会等待，Ctrl+C可结束。格式/接口错误先局部修订，再交回主循环。缓存损坏或框架异常保存证据并等待修复，不伪装成缺资料、仿真成功或已交付。没有真正进展的无限循环是可能的，使用者可主动停止。

断点包含master的phase/cycle、模型、测试结果和累计用量。相同输入、代码与路由用相同runtime加--resume；升级软件不能直接打开旧代码身份的断点，必须使用新输出目录。原实验不覆盖。

UC2845的31项接口及16项LTspice校准一并打包。参考资料/方法资格仍有缺口：启用持续模式不会凭空补出数字化曲线或使初始模型达标。本版只做离线故障注入和执行器回归；真实API持续验收需用户启动。
