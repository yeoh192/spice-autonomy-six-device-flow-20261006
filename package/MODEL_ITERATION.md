# 批次模型迭代
新增阶段在测试开发和草案修复之后执行。固定活动测试、参考值、手册条件、端口与验收标准，Qwen修改参数/结构，GLM审查实际差异，每个候选完整回归，确认改善且已通过项目不退化才保留，否则回退并反馈下一轮。普通优化最多3轮，批次入口诊断最多6个物理试验；空补丁、审查修订与分析单独计数，总API、仿真、修复和时限预算仍共享。
目前BUK23项与1N4148六项进入模型迭代。其他4器件缺正式建模候选或有资格的活动测试，明确阻塞；不会把参考模型当成新建模成果。新增参考接口方法尚未获得正式候选资格，不能直接并入交付回归。整个器件手册覆盖仍单独审计。
旧仿真仅在模型、实际电路、运行器、解析器签名、原文件哈希以及真实成功状态均匹配时复用；原模型和状态不修改。新模型输出engineering_candidate.lib，缺口未闭合不称正式交付。
RUN_MODEL_ITERATION.sh可为当前已跑批次单独执行新阶段，无需重新做前面的API测试开发。RUN_SIX_DEVICES.sh为新任务自动包含新阶段。真实API和仿真由用户启动。

## v0.3.7 有界恢复循环

优化回退后，诊断入口接收完整的回退提案、参数槽位、带方向的残差、程序保留理由和结果审查。空补丁或预审退回会自动反馈修订，不消耗物理试验槽位；连续3次修订失败才结束该循环，纯分析最多2次。已批准并预留的试验在中断后继续完成，不重复计数或请求。

程序从实际模型提取参数槽位，不绑定Kp或某个器件。相同基线上，同一单参数两次实测未获保留后，下一提案须选择其他参数或联合方向；未执行的格式错误和预审拒绝不算物理失败。改善的局部试验可以提升为完整回归补丁。每个保留补丁都经过完整活动回归、程序防退化检查和结果审查；回退不改变活动模型。

这些是有限预算内的恢复规则，并非无限搜索或任意代码自修复。批次原总预算仍为24次API、12次修复、1800秒及按活动测试数计算的仿真上限；任一总预算先耗尽就保存状态和缺口。认证、配置和证据损坏故障仍明确停止。典型值、曲线容差、手册条件和待判定参考依据均不放宽。真实Qwen/GLM拟合效果尚待新版本运行验证。

## v0.3.8 分离诊断与修复设计

真实BUK回归案例暴露了角色误解：诊断Agent连续返回分析，随后声称不能提交实际修改。本版本在第一条诊断或修订反馈后切换到独立的model_repair_designer角色，明确授权受限修改，动作只允许experiment、patch或有实测依据的stop。分析不会自动转换为未经审查的模型修改；设计仍须经过差异审查、真实试验、完整回归及结果审查。

规划上下文保留失败项的详细实测证据、全部活动测试的保护目标和已有回退记录，去除重复优化反馈与结果元数据。完整证据继续保存本地哈希；反复压缩不再覆盖原有曲线带方向残差。此处的阶段切换和证据压缩已通过离线故障测试，真实API行为仍需重跑验证，未解决42项待判定或完整手册覆盖。

## v0.3.9 正式接口合同

上述模型角色统一接入model-interface-1；字段/动作错误与有效审查revise分开处理。无效输出先得到一次带字段错误码的自动格式修订，耗尽后交回设计循环；两次物理API请求都计入总预算，不进入真实仿真槽位。输入在调用前核验，执行前比对实际差异，执行后核验候选哈希。合同文档与JSON Schemas见INTERFACE_CONTRACTS.md。真实API拟合效果仍待实跑验证。

BUK演示可设置 `BUK_TEST_SCOPE=core` 调用 RUN_BUK_AUTOMATION.sh，仅运行原有23项测试并执行大模型迭代和完整的23项回归。默认extended仍为65项。core结果只代表23项范围，手册全覆盖仍单独报告。审查请求现在也在最终发送前压缩采样详情和冗余哈希，保留全部电路与冻结目标，预留恢复反馈空间。
